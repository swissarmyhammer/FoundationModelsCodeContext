## Problem
In a full `swift test` run on 2026-10-17 (911 tests), `ProcessInstallRunnerTests.cancellationTerminatesTheChildPromptly()` failed: `elapsed < .seconds(5)` was false, `elapsed` was 6.17 seconds. In the same window, many tests of other suites reported "passed after 47 seconds", thus the test process did not get CPU time for a long period. The same test passed in 0.110 seconds when it ran alone (`swift test --filter "ProcessInstallRunnerTests|ChildStandardInputTests"`).

The test measures real time from `task.cancel()` to `task.value`. Under load, the time includes the time that the cooperative pool and the dedicated drain thread wait for the CPU. The fixed limit of 5 seconds is a real-time assertion, thus the test can fail when the machine is busy.

Found during ^w29j74j. The change of ^w29j74j (stdin of each child is the null device) does not touch the cancellation path.

## Change
- Make the assertion independent of the scheduler. For example, assert that the child is killed (the pid is gone, or the run ends with a kill signal) and that the run does not wait for `sleep 60` to end on its own, with a limit that is far below 60 seconds but far above the scheduler delay.

## Acceptance criteria
- [ ] The test proves that cancellation kills the child, not that the scheduler is fast.
- [ ] The full unit suite passes.
