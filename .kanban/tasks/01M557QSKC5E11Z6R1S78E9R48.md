title: The LSP index worker must not repeat a failed batch with no wait
---
## Problem
- `LSPIndexWorker.run` (`Sources/FoundationModelsCodeContext/Index/LSPIndexWorker.swift:150-163`) waits only when there are no dirty files or no session. When `indexFiles` fails for all files in a batch, it starts again at once.
- A file stays dirty (`lsp_indexed = 0`) when `syncOpen` or `documentSymbols` fails (`:343`) and when the store write fails (`:379`).
- `dirtyFiles` (`:251-271`) takes the first files by path order. Thus, if one batch fails each time, the worker gets the same batch again and again with no wait. This uses CPU and sends requests to the server with no stop, and the other dirty files are never indexed.
- In the Rust code, a skipped file is marked done (`lsp_indexed = 1`) for this reason.

## Change
- Count the failures for each file in the worker. After a small number of failures (for example 3), mark the file done and log a warning one time. A new watcher event for the file makes it dirty again.
- When a full batch gives no success, wait (`configuration.sessionUnavailableSleep` or a new backoff value) before the next batch.
- Do not change the current skip paths that already mark the file done (`:321`, `:329`).

## Tests
- With a fake session where `documentSymbols` always throws, the worker does not send more than N requests for one file, and the file is then marked done.
- With one file that always fails and one good file, the good file is indexed.
- A batch where all files fail makes the worker wait on the clock before the next batch.

## Acceptance criteria
- [ ] A file that always fails does not block other files.
- [ ] The worker does not loop with no wait.
- [ ] The tests above pass.
